Network settings

  1. /etc/resolv.conf should have:
    • nameserver 192.168.1.17
  2. /etc/sysconfig/network should have:
    • NETWORKING=yes
    • HOSTNAME=hostname.geophysics.princeton.edu
    • GATEWAY=192.168.0.1
    • GATEWAYDEV=eth0
  3. /etc/sysconfig/network-scripts/ifcfg-eth0 should have (I believe last three lines are redundant):
    • DEVICE=eth0
    • ONBOOT=yes (disable to "no" when starting up unplugged)
    • BOOTPROTO=protocol where protocol is DHCP for gezelle (the laptop) or STATIC for melchior (the desktop)
    • IPADDR=192.168.0.XX where XX is 46 for melchior and 162 for gezelle
    • NETMASK=255.255.255.0
    • GATEWAY=192.168.0.1
  4. Restart network settings with service network restart or with /etc/init.d/network restart
  5. Check settings with netstat -rn
  6. Check settings with host hostname to see if the zone maps have been updated. This will return IP address etc.

SSH Client and Server

I was able to do ssh out of, but not ssh into my machine.
  1. Check if the sshd daemon is running: service sshd status
  2. Check if the Redhat Package Manager has installed sshd: rpm -qa | grep ssh
  3. Both openssh-server and -client need to show up; they didn't
  4. Get package from ftp ftp.princeton.edu, cd /redhat/linux/updates/7.3/en/os, mget openssh*
  5. Install/update package: rpm -Uvh openssh*. You don't need to keep the rpm files after this.
  6. Start ssh daemon; service sshd start
  7. chkconfig sshd will turn it on automatically in the future
  8. Check status with chkconfig --list sshd
  9. Add sshd: 192.168.1.3 to the /etc/hosts.allow file so my machine will allow ssh into it from geophysics.princeton.edu machines.
  10. geophysics.princeton.edu's IP Address is 128.112.22.111 - it's outside, and will rerout it to 192.168.1.3 so it'll look like 192.168.1.3 to me for incoming ssh.
  11. On the web, www.geophysics.edu will look like 192.168.0.3

Firewall implementation to fix mount or ssh problems

When trying to mount external disk, got in trouble. When trying to ssh into my machine, got error: "port 22 connection refused". Fixed it as follows:
  1. See what ipchains is up to /sbin/ipchains -L or /sbin/chkconfig --list ipchains or service ipchains status.
  2. Need to turn it off: service ipchains stop
  3. This now allows ssh into the machine. But not the problem with mount.
  4. For that, do more: /sbin/chkconfig --level 0123456 ipchains off to turn ipchains off for all runlevels. Needed to specify runlevels explicitly, otherwise didn't turn all of them off for some reason.
  5. runlevel will give you a status.
  6. Check /etc/sysconfig/ipchains and /etc/init.d/ipchains to get the idea.
See further under How to mount a file system.

Printer setup

You can follow the printconf-gui, but for tek740 you need to copy /var/spool/lpd/tek740/lowrtray.ps, /var/spool/lpd/tek740/middtray.ps, and /var/spool/lpd/tek740/upprtray.ps from somewhere, as well as the /bin/tek740 scripts. Also create (touch) the (misspelled) /var/spool/lpd/tek740/transparancy_use file. Make sure that the directory is accessible (chmod +x) and transparancy_use writeable.

To change hostname
