A complete overhaul after trouble

  1. From the Windows XP Home Edition Reinstallation disk, deleted all partitions and reformatted drive. Space available is 38,155 MB.
  2. From the Inspiron 2650 System Software Reinstallation disk, install. Not really necessary.
  3. From the Roxio Reinstallation disk, install Complete CD Creator software. Optional.

Preliminary steps

    Gather information about the computer, cards, screen, etcetera, from within Windows XP before you start, as follows:

  1. Type specifications in the Help and Support Center
  2. Type msconfig in the Run... Start menu option. Turns out there was a "ghost" XP boot file; checking that particular boot.ini made it go away.
  3. Find and run device manager to check for installed devices
  4. Change display settings to find out it allows maximum 1024x768 pixels

Partitioning the hard disk under installed Windows XP

  1. Using PowerQuest PartitionMagic 7.0 (serial number can be bogus and the program will still continue; don't bother looking one up), make a new partition (which is automatically called E:) as logical, FAT (one other choice, NTFS, will not work ), and make this very small, e.g. 8 MB.
  2. Resize the NTFS Windows C: partition (I chose 7000 MB on the 20 GB disk and 14000 MB on the 40 GB disk), while checking that the freed-up space be given to your just created dummy partition
  3. Reboot, hold F2 to enter BIOS, make sure it boots from the CDROM before the hard disk. Save and exit.

Partitioning the hard disk under Red Hat 7.3 while installing it

    Note: Usually there can only be four primary partitions, and /boot needs to be in the first 1024 blocks. This is possibly forced by the program, although there is an option later on to allow for a /boot in posterior sectors.

  1. Put in Red Hat Installation CD 1 of 3 and reboot again. Note that CTRL+ALT+DELETE will leave the installation program in most cases.
  2. Install in graphical mode, as a server (not laptop).
  3. Choose generic 105-key keyboard, Logitech Mouseman Wheel USB mouse.
  4. Elect to use diskdruid program, rather than fdisk. You'll find a bunch of partitions already there. With the laptop might have come a Dell Utility partition /dev/hda1/, this was not there anymore after the XP reinstallation. Guess it's not critical.
  5. Delete whatever else there might be that is not Windows, but keep the Dell Utility if it is there (in which case this is /hda1 and of type vfat) and the Windows partition, which is is primary partition called /hda1 (or /hda2 if Dell Utility is there), and which is of type NTFS. It's not a bad idea at this point to define a mountpoint for Windows as e.g. /usr/windows, although later on you can use mount for that purpose.
  6. Start adding partitions. First, add a (forced to be) primary partition with mountpoint /boot and of type ext3. It'll automatically be called /hda2 (we now give the case where Dell Utility is not present; if not all numbers are to be augmented by 1).
  7. Second, add the (forced to be) primary partition with mountpoint /home and of type ext3. This will become /hda3, and you want to fill it to capacity.
  8. Keep adding, one after another, logical (not primary partitions of the following types/sizes/mountpoints according to the table below.

    Device nameTypeMount pointSizeComment
    /hda1NTFS/usr/windows14000 MBwas already there, and maybe also the Dell Utility partition
    /hda2ext3/boot48 MBprimary, make this the first you create
    /hda3ext3/homefill to capacityprimary; even if created out of order will get a number less than 4.
    /hda5ext3/usr/8096 MB
    /hda6ext3/usr/local4096 MB
    /hda7ext3/var2048 MB
    /hda8fat16/shared2048MBbigger may not be allowed
    /hda9ext3/tmp1024 MB
    /hda10ext3/512 MB
    /hda11swapnot applicable512 MBat least twice the RAM, but edit to fill capacity if there is any space left after the full partitioning
    /hda4extendedjust a subdivided headerencompasses the logicals

  9. Put the boot loader (GRUB) in the master boot record (MBR) indeed.
  10. Add boot labels to /dev/hda10 (ext3) e.g. as RedHat Linux 7.3 and /dev/hda1 (ntfs) as Windows XP. If it believes there is a DOS boot on the shared disk, it won't be true and simply deleting its label will get rid of it as a GRUB option. Later on, check /boot/grub/grub.conf.
  11. Set GRUB password. Accept eth0 and DHCP and activate ONBOOT.
  12. Set security to high and use default firewall rules.
  13. Keep languages Dutch, French, Icelandic, Greek.
  14. Set root password and new user names.
  15. Install GNOME, KDE, X and Classic X.
  16. Definitely create a boot disk. This changes with every individual installation, so you need to keep one current.
  17. Choose the NVIDIA card but see below.
  18. Monitor specs are Dell 1024X Laptop Display and next, make sure to adjust to a text login only. Without the proper graphics card installed, the graphical login will cause you much, much trouble. Check True Color (24 bit) and screen resolution 1024x768.
  19. Do NOT test settings - system will crash, and CTRL+ALT+BACKSPACE which usually leaves the X system, won't work. Also CTRL+ALT+F7 to switch to text login won't work. (If it crashed like this, pushing all sorts of buttons might cause it to reboot. Need to start from scratch. Put in Disk 1 again, go through full system installation, not upgrade, including mountpoint redefinitions of already made partitions.
  20. Text login hung. CTRL-Q seemed to force quit. CTRL-F1 and CTRL-F2 switch login modes.

Installation of the NVIDIA driver:

    Try to do this as root from a text login asap.

  1. ftp download.nvidia.com
    cd XFree86_40
    cd 1.0-3123
    bin
    get NVIDIA_GLX-1.0-3123.i386.rpm (1768048 bytes)
    get NVIDIA_kernel-1.0-3123.rh73up.i686.rpm (396965 bytes)
  2. Take the right version, if not, you'll get complaints about unresolved symbols. Keep the files in /usr/src/redhat/RPMS/i686.
  3. Check file sizes, etc, to see if they have been downloaded properly, if not, you'll get cpio:read errors down the line.
  4. Type rpm -ivh NVIDIA_kernel-1.0-3123.rh73up.i686.rpm to install; you should get only ### if installation is successful.
  5. Type rpm -ivh NVIDIA_GLX-1.0-3123.i386.rpm to install. Some (stale) lib files may be renamed in the process.
  6. See /usr/share/doc/NVIDIA_GLX-1.0/README for more documentation and a sample XF86Config-4 file. This is a sample file of the type that will be read by startx and used to configure the X-server.
  7. Remove Load "dri" and Load "GLCore" from /etc/X11/XF86Config-4, change the Device Driver "nv" to Driver "nvidia", and make sure you have not uncommented Load "glx". Switch CTRL and CAPS in this file too, where indicated. Remove Driver "blabla" from Section Screen.
  8. Installation should have resulted in a file called /lib/modules/2.4.18-3/kernel/drivers/video/NVdriver (not a text file) that startx will want to load every time; /sbin/modprobe and /sbin/insmod can be used to load modules forcefully. File /sbin/lsmod (not a textfile) should be updated if the module is loaded.
  9. /sbin/lspci can tell you whether nVidia is on the PCI list
  10. Messages from startx will appear in /var/log/XFree86.0.log (Errors as (EE)); this file will tell you that the file loaded is /etc/X11/XF86Config-4. This latter file is what you need to update (rather than replace), with the sample provided by NVIDIA. If you've listed NVidia's card and the monitor during installation, this file will be simple, and updating them even simpler.
  11. Check here for my current XF86Config-4 file.

Which operating system installed?

Type uname -r to find it as 2.4.18-3, and type uname -m to find the machine (hardware) type is i686. Note that UP=uniprocessor, SMP=simultaneous multiprocessor. Also, dmesg gives a lot of useful system information.

Optimizing the hard disk The default setting of support for 16-bit EIDE is on. However, modern hard disks are capable of 32-bit I/O. To check the options start a terminal and give the following command: hdparm /dev/hd* (a,b or c- this depends on your configuration. Try 'a' first) You will see something like this: mulcount = 0 (off) I/O support = 0 (default 16-bit) unmaskirq = 0 (off) using_dma = 0 (off) keepsettings = 0 (off) nowerr = 0 (off) readonly = 0 (off) readahead = 8 (on) geometry = 1240/255/63, sectors = 199311844, start = 0 hdparm -Tt /dev/hda gives buffered and unbuffered performance figures for your hard disk-IDE controller combination. hdparm -c1 /dev/hda will set the disk to use 32-bit I/O hdparm -d1 /dev/hda enables DMA Test the performance by giving the command hdparm -Tt /dev/hda You should definitely see an improvement in performance. To keep the settings, type hdparm -k1 /dev/hda

Information on how to mount Windows disks without sweat:

  1. Which RPM ?

    It is important to install exactly the same version of NTFS kernel module as the kernel you have installed. A quick way to find the version is to use the whichrpm script. Save the file and run it. Then go to the install section. This script, just automates what we will do next. First we need to decide which release you have: cat /etc/redhat-release and you should see e.g. the following response: Red Hat Linux release 7.3 (Valhalla). Next find out your kernel version: uname -r. You should see a response something like one of these: 2.4.18-3. The version might also have one of the following suffixes: smp bigmem BOOT. If the result ends with smp then you have a multi-processor computer (you probably already knew that). Next find out what sort of processor you have. This command will ask which rpm RedHat installed for you. Users with a multi-processor machine should replace kernel with kernel-smp: rpm -q --queryformat "%{ARCH}\n" kernel. Most people will have an i686 processor (a recent Pentium computer). Other options are athlon, i586 or i386.

  2. Install

    You must be root for the rest of the commands. The examples will continue as if you downloaded kernel-ntfs-2.4.18-3.i686.rpm. Next install the rpm: rpm -ihv kernel-ntfs-2.4.18-3.i686.rpm. There should be no errors, just #'s. Note: newer NTFS RPMs will also print a message telling you if install succeeded. This is the only command we actually needed, but we'll go on and test what we have done. Next load the kernel module /sbin/modprobe ntfs. There should be no output. If there are a lot of error messages, get help. Next, dmesg | grep NTFS should return NTFS driver v1.1.22 [Flags: R/O MODULE]. We can now check that the kernel really understands NTFS. The output may vary slightly, but you are looking for the entry ntfs.

    cat /proc/filesystems nodev rootfs nodev bdev nodev proc nodev sockfs nodev tmpfs nodev shm nodev pipefs ext3 ext2 nodev ramfs nodev devpts ntfs

  3. Mount First you need to know which device your NTFS Volume is on and you need to create a directory as a mount point. Type: /sbin/fdisk -l; the output might look like:

    Disk /dev/hda: 64 heads, 63 sectors, 4465 cylinders Units = cylinders of 4032 * 512 bytes Device Boot Start End Blocks Id System /dev/hda1 1 2125 4283968+ 07 NTFS/HPFS /dev/hda2 2126 19851 35735616 0f Win95 Ext'd (LBA) /dev/hda5 * 2126 4209 4201312+ 83 Linux /dev/hda6 4210 4465 516064+ 82 Linux swap

    Then, type mkdir /mnt/windows and mount /dev/hda1 /mnt/windows -t ntfs -r -o umask=0222 if you want read-only, or -o umask=002 for read-write (but that is not supported, it seems). See man mount for further options. Hopefully everything is working for you now. Check /etc/mtab and update /etc/fstab accordingly.
